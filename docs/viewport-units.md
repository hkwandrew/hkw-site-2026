# viewportUnits.js

`src/styles/viewportUnits.js` owns the site's viewport-scaled design pixel system. It lets component styles keep using design-authored `px` values while the rendered CSS scales those values against fixed desktop and mobile design viewports.

The utility has two jobs:

- Define the custom property that represents one scaled design pixel.
- Convert CSS declaration values from `px` to `calc(<number> * var(--hkw-viewport-px-unit))`.

## Design Viewports

The file exports four design viewport constants:

| Constant | Value | Purpose |
| --- | ---: | --- |
| `DESKTOP_VIEWPORT_WIDTH` | `1440` | Desktop design width used for width-based scaling. |
| `DESKTOP_VIEWPORT_HEIGHT` | `1024` | Desktop design height used for height-based scaling. |
| `MOBILE_VIEWPORT_WIDTH` | `393` | Mobile design width used below the mobile breakpoint. |
| `MOBILE_VIEWPORT_HEIGHT` | `640` | Mobile design height used below the mobile breakpoint. |

The custom property name is exported as `VIEWPORT_PX_UNIT_CUSTOM_PROPERTY` and currently resolves to:

```css
--hkw-viewport-px-unit
```

## Runtime Model

`GlobalStyle` defines `--hkw-viewport-px-unit` on `:root`.

For desktop, the value is:

```css
min(0.06944vw, 0.09766vh)
```

That is the smaller of:

- `1 / 1440 * 100vw`
- `1 / 1024 * 100vh`

For mobile, `GlobalStyle` switches the value inside `@media (max-width: 1024px)` to:

```css
min(0.25445vw, 0.15625vh, 1px)
```

That is the smaller of:

- `1 / 393 * 100vw`
- `1 / 640 * 100vh`
- `1px`

The `min(width scale, height scale)` shape keeps a design pixel from being sized only by viewport width. If the viewport is short for its width, the height term controls the scale. If the viewport is narrow for its height, the width term controls the scale.

The mobile value also includes `1px`, so mobile design pixels can shrink below the design size but do not upscale above it.

## Styled-components Integration

`src/main.jsx` wraps the app in:

```jsx
<StyleSheetManager stylisPlugins={[viewportPxToVwPlugin]}>
  ...
</StyleSheetManager>
```

That makes `viewportPxToVwPlugin` run against styled-components' generated CSS declarations. The plugin runs after template interpolation, so it catches both literal CSS and values interpolated from props or theme tokens.

Example styled-component input:

```js
const Example = styled.div`
  width: ${({ $width }) => $width};
  padding: 72px;
`
```

With `$width='144px'`, the emitted declaration values become:

```css
width: calc(144 * var(--hkw-viewport-px-unit));
padding: calc(72 * var(--hkw-viewport-px-unit));
```

The exported plugin name, `viewportPxToVwPlugin`, is historical. The plugin now converts to the custom viewport pixel unit, not directly to `vw`.

## Inline Style Usage

The Stylis plugin only sees CSS generated by styled-components. It does not process React inline style objects.

Use `convertCssPxToViewportUnit()` for inline styles or inline custom properties that should participate in the same scaling system:

```jsx
const style = {
  fontSize: convertCssPxToViewportUnit('32px'),
  '--about-float-y': convertCssPxToViewportUnit('-10px'),
}
```

Current non-test inline usage appears in:

- `src/app/ErrorBoundary.jsx` for error-state typography sizes.
- `src/routes/about/AboutPage.jsx` for floating animation custom properties.

## Export Reference

### `getViewportPxUnitValue(viewportWidth)`

Converts one design pixel into a width-based `vw` unit.

```js
getViewportPxUnitValue(1440)
// "0.06944vw"
```

### `getViewportPxHeightUnitValue(viewportHeight)`

Converts one design pixel into a height-based `vh` unit.

```js
getViewportPxHeightUnitValue(1024)
// "0.09766vh"
```

### `getFittedViewportPxUnitValue(viewportWidth, viewportHeight)`

Returns a `min()` expression that chooses the smaller width-based or height-based design pixel.

```js
getFittedViewportPxUnitValue(1440, 1024)
// "min(0.06944vw, 0.09766vh)"
```

This is used for the desktop root value.

### `getCappedViewportPxUnitValue(viewportWidth, viewportHeight)`

Returns the fitted value with a `1px` cap.

```js
getCappedViewportPxUnitValue(393, 640)
// "min(0.25445vw, 0.15625vh, 1px)"
```

This is used for the mobile root value.

### `convertCssPxToVw(value, viewportWidth = DESKTOP_VIEWPORT_WIDTH)`

Converts `px` values in a CSS value string to direct width-based `vw`.

```js
convertCssPxToVw('72px')
// "5vw"

convertCssPxToVw('19px', 393)
// "4.83461vw"
```

This helper is width-only. Use it only when that is the intended behavior. Most app styling should use the custom-property path instead.

### `convertCssPxToViewportUnit(value)`

Converts `px` values in a CSS value string to the responsive custom-property form.

```js
convertCssPxToViewportUnit('72px')
// "calc(72 * var(--hkw-viewport-px-unit))"

convertCssPxToViewportUnit('-0.48px')
// "calc(-0.48 * var(--hkw-viewport-px-unit))"
```

If the parsed number is zero, the helper returns `0`:

```js
convertCssPxToViewportUnit('0px')
// "0"
```

### `viewportPxToVwPlugin(element)`

Styled-components passes Stylis declaration nodes to this plugin.

The plugin exits unless:

- `element.type` is `decl`.
- `element.children` is a string.
- `element.props` is not `--hkw-viewport-px-unit`.

It skips the `--hkw-viewport-px-unit` declaration because that value intentionally contains raw `vw`, `vh`, and `1px` terms. Rewriting it would make the scale definition self-referential.

When conversion changes a declaration, the plugin updates:

- `element.children`
- `element.value`
- `element.return`

That is the mutation shape styled-components expects from a Stylis plugin.

## Conversion Parser

All string conversion goes through `convertCssPxValues(value, formatPxValue)`.

The parser scans one character at a time so it can distinguish actual CSS lengths from text that merely contains `px`.

It converts numeric `px` tokens matching:

```js
/^[-+]?(?:\d*\.\d+|\d+\.?\d*)px\b/i
```

Supported examples include:

- `72px`
- `-0.48px`
- `.5px`
- `10PX`

The conversion is case-insensitive for the unit.

The parser leaves these values unchanged:

- Non-string values.
- Strings that do not contain `px`.
- Quoted strings such as `"literal 30px"`.
- Escaped characters inside quoted strings.
- `url(...)` function contents, including quoted URLs.

This protects asset references such as:

```css
background-image: url('/images/card-72px.png');
```

The parser still converts `px` values inside other CSS functions:

```css
clamp(16px, 2vw, 32px)
```

becomes:

```css
clamp(
  calc(16 * var(--hkw-viewport-px-unit)),
  2vw,
  calc(32 * var(--hkw-viewport-px-unit))
)
```

## Number Formatting

The conversion helpers use `Number.parseFloat()` and round non-zero numbers to five decimal places.

`Number(...)` wraps the rounded string to trim unnecessary trailing zeros:

```js
convertCssPxToVw('72px', 1440)
// "5vw", not "5.00000vw"
```

Zero, negative zero, and `NaN` parse results return `0`.

## Practical Rules

- In styled-components CSS, write design-authored `px` values normally when they should scale with the site.
- In inline React styles, call `convertCssPxToViewportUnit()` for any `px` value that should scale.
- Do not use `convertCssPxToVw()` for general layout unless width-only scaling is explicitly desired.
- Do not put values that must remain literal physical pixels in styled-components as `px`; the plugin currently has no broad opt-out for declaration values.
- Keep `--hkw-viewport-px-unit` defined in global CSS before relying on converted values.
